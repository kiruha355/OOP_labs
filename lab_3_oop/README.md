# Лабораторная работа 3, вариант 7

Множество телефонов `PhoneNumberSet` на динамическом массиве. Структура проекта,
консольное меню и Google Test оформлены по примеру лабораторных 1 и 2.

## Реализация

- `PhoneNumber` оставляет только цифры: `+7 (999) 123-45-67` и `79991234567`
  равны. Начальные нули сохраняются. Замена `8` на `7`, проверка длины и кода
  страны в задании не предусмотрены и не выполняются.
- Номер хранится в `char*`, множество — в `PhoneNumber*`. Оба класса реализуют
  правило пяти, глубокое копирование и копирующее присваивание через copy-and-swap.
  Перемещения помечены `noexcept`; перемещенный объект пуст и пригоден для работы.
- Добавление идет в конец после линейного поиска дубликата. Емкость растет
  `0 -> 1 -> 2 -> 4 -> 8 ...`. Удаление заменяет элемент последним, без сдвига.
- Реализованы `add`, `remove`, `contains`, `()`, `size`, `empty`, `+=`, `-=`,
  `|`, `&`, `-`, `==`, `!=` и `<<`. Дополнительно есть `capacity` и `swap`.
  Разность использует вложенные циклы; равенство не зависит от порядка хранения.
- Вывод: `{ 79991234567, 123 }`, пустое множество: `{ }`.
- В классах нет шаблонов, контейнеров STL, `std::string` и умных указателей.
  Потоки строк используются только в тестах для проверки вывода и создания данных.

Пустой номер на уровне класса — пустая последовательность цифр; одинаковые пустые
значения не дублируются. Меню просит ввести хотя бы одну цифру. Ограничение ввода
в меню — 255 символов; сам класс не ограничивает длину номера.

## Сборка и запуск

Требуются CMake 3.20+, компилятор C++20 и установленный Google Test.
Команды выполняются из корня репозитория:

```sh
cmake -S lab_3_oop -B build/lab_3_oop
cmake --build build/lab_3_oop
ctest --test-dir build/lab_3_oop --output-on-failure
```

Программа: `build/lab_3_oop/main_programm` (на Windows — `main_programm.exe`).
В меню можно заполнять множества A и B, проверять телефоны и выполнять операции.
При сборке с несколькими конфигурациями добавьте `--config Debug` к сборке,
`-C Debug` к CTest; программа будет в подкаталоге `Debug`.

Для MSYS2 UCRT64 используйте генератор Ninja и путь к Google Test:

```sh
cmake -S lab_3_oop -B build/lab_3_oop -G Ninja -DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/g++.exe -DCMAKE_PREFIX_PATH=C:/msys64/ucrt64
```

Если нужен только запуск программы без Google Test:

```sh
cmake -S lab_3_oop -B build/lab_3_program -DBUILD_TESTING=OFF
cmake --build build/lab_3_program
```

## Проверка памяти

В Linux / WSL с GCC или Clang:

```sh
cmake -S lab_3_oop -B build/lab_3_asan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer -g"
cmake --build build/lab_3_asan
ASAN_OPTIONS=detect_leaks=1 ctest --test-dir build/lab_3_asan --output-on-failure
```

Тесты проверяют нормализацию, дубликаты, порядок после удаления, рост емкости,
независимость копий, перемещения, самоприсваивание, операторы и формат вывода.
Стресс-тест добавляет 1000 номеров, повторно проверяет дубликаты и удаляет все номера.
